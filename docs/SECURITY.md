# 安全说明

## 敏感信息

以下内容禁止提交到 Git 仓库，也禁止出现在日志中：

- `FUDAN_USERNAME`：复旦统一身份认证账号
- `FUDAN_PASSWORD`：复旦统一身份认证密码
- `FUDAN_TOTP_SECRET`：可选的动态验证码种子
- 预约系统和 UIS 的 Cookie
- `QQ_SMTP_USERNAME`：QQ 邮箱账号
- `QQ_SMTP_AUTH_CODE`：QQ 邮箱 SMTP 授权码
- `NOTIFICATION_EMAIL`：通知收件地址
- CAS service ticket：仅在单次登录过程中通过标准输入传给本机 Node 校验桥，不保存

部署时只能使用 GitHub Secrets 或 Cloudflare Secrets。本地联调可以使用命令行交互输入，也可以把真实值写入已被 Git 忽略的 `.env`。`.env.example` 是会提交到 GitHub 的空白模板，禁止填写真实值。QQ SMTP 使用的是单独生成的授权码，不是 QQ 密码。

## 日志规则

日志可以包含事件类型、场馆名称、球类、日期、时间、结果类别和简短的请求追踪编号。

日志不得包含：

- 认证接口的原始响应正文
- 请求头和 Cookie
- 手机号、邮箱地址、姓名
- 密码、TOTP 种子、SMTP 授权码等凭据

Node 校验桥只接受预约站点 HTTPS 地址。普通查询只允许场馆列表、日程、预约列表，以及预约表单所需的资源详情和账号联系方式五类 GET
接口；预约提交只能通过固定的 `book_resource` 操作访问体育场馆预约端点，
不接受任意 POST，也不会提供取消预约能力。命令行默认不调用这两个提交操作。

预约提交会读取登录账号已经填写的手机号，并按网页预约表单的格式提交；手机号不会写入配置、日志
或通知内容，也不要求用户额外配置或校验手机号。

只读联调命令只输出场馆编号、场馆名称、未结束预约数量，以及各时段的空余子场地数量。接口返回的预约人信息不会进入输出，也不会输出任何认证材料。

## 绝不自动取消

项目有意不实现取消预约能力。任何已有预约都不会为了更高优先级的候选时段而被自动取消。

## 凭据泄露后的处理

如果敏感信息曾被提交、粘贴到公开位置或打印到日志，应立即：

1. 修改复旦统一身份认证密码（如果泄露的是该密码）。
2. 在 QQ 邮箱中撤销并重新生成 SMTP 授权码（如果泄露的是授权码）。
3. 更新 GitHub Secrets 和 Cloudflare Secrets。
4. 让现有登录会话失效，并检查近期预约和登录记录。
